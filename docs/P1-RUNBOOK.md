# P1 runbook — shipping the image set without overflowing a chat

P1 is 60 generated images plus 8 derived social cards. The reason "execute P1" fails
with *"Your message is too long to be processed"* is that every generated image stays
in the conversation as image data, so a thread dies after ten or fifteen of them. The
fix is not a shorter prompt: it is running P1 as twelve small, resumable batches with
all the detail held in the repo.

## Files

| File | Job |
|---|---|
| `docs/p1-manifest.json` | All 60 shots: batch number, generation size, crop ratio, final dimensions, byte budget, alt text and the full prompt. Generated by `build/p1_manifest.py`. |
| `docs/p1-state.json` | Per-shot `pending` / `accepted`, attempt count, last rejection reason, output file sizes. |
| `docs/image-log.md` | Written automatically: every accepted image with the prompt that produced it (§11.6 step 6). |
| `build/images.py` | The whole pipeline: crop, downscale, shared grade, AVIF q55 + WebP q78, budget enforcement, state, log, social cards. |
| `build/pic.py` | `pic(shot_id)` for new templates, and an automatic `<img>` → `<picture>` upgrade applied inside `build_site.write()`. |

Nothing needs hand-editing per image. One command per accepted shot.

## Commands

```
python3 build/images.py status          # progress by batch
python3 build/images.py next 4          # the 5 prompts for batch 4
python3 build/images.py add SHOT_ID SRC # crop, grade, encode, budget, log, accept
python3 build/images.py reject SHOT_ID "reason"
python3 build/images.py og              # derive the 8 1200x630 cards from accepted heroes
python3 build/images.py verify          # dimensions + budgets on everything accepted
python3 build/make.py                   # rebuild pages; accepted shots become <picture>
```

## The batch prompt

**Start a new chat for every batch.** Paste this, changing only the number:

> repo: beniwt292-cmyk/veneta-website-redesign (token in bin). Run P1 batch 4 per
> docs/P1-RUNBOOK.md: `python3 build/images.py next 4`, generate those shots at the
> stated size, `add` each one, then `verify`, `og`, `make.py`, and commit as
> beniwt292-cmyk <280820324+beniwt292-cmyk@users.noreply.github.com>.
> Reply with one line per shot, nothing else.

## Rules for the agent running a batch

1. **Never read `MASTER_PLAN.md`.** The manifest already carries the art direction.
2. **Five generations maximum per chat.** Stop at the batch boundary even if there is
   room left.
3. **Never preview or re-display an image.** Judge it once from the generation result
   against §11.5, then `add` or `reject`.
4. **Rejections are not re-rolled in the same chat.** `reject` with a reason; the shot
   returns to pending and is picked up by a later batch, with the reason shown by `next`.
5. **Reply with one line per shot.** No prompt echoing, no file dumps, no summaries of
   the plan.
6. **One commit per batch**, subject line `P1 batch N: <sets touched>`, body listing
   accepted and rejected ids and the §15 gate result.

## Batch map

Batches 1–2 the homepage LCP hero and all 9 category heroes, 3–4 the 8 product index
cards, 4–6 the 12 macro materials, 7–8 the 9 opacity triptychs, 8–9 the 6 room scenes,
10 the 4 style scenes, 10–11 motorization and child safety, 11–12 trade and commercial.
Run them in order: the social cards derive from heroes, so batch 1 must land first.

## Amendments to MASTER_PLAN.md §11 encoded in the manifest

- Image generation maxes out at 1536px long edge and offers only 1:1, 3:2 and 2:3, so
  the §11.1 long edges (2400/2000/1800) are unreachable. Long edges are native and never
  upscaled: heroes 1536, safety 1365, cards and macros 1024, triptychs 1000.
- Non-native ratios (16:9, 4:5, 3:4, 4:3) are centre-cropped from the three generatable
  sizes, so every prompt asks for framing that survives the crop.
- "Generate at 2× then downscale" is replaced by "generate native, then grade": the grade
  in §11.6 step 2 still runs, and the mild negative clarity plus 8% grain does the same
  artefact-suppression job.
- The 8 `og:image` files are script-crops of accepted heroes, not generations.
- The 6 guide diagrams are hand-built SVG. AI diagrams need lettering, which fails the
  §11.5 rejection checklist by definition.

Net: 74 assets in §11.1 become 60 generations, 8 derived crops and 6 SVGs.

## Replacement path

Unchanged from §11.6. Real photography follows the same shot list, lens and light
direction, and swaps 1:1 by keeping the shot id in the filename.
